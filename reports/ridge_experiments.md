# Ridge USDRUBF: validation 2025

Расчёт от 2026-11-24, ветка `feature/direct-ridge-experiments`. Основной эксперимент — direct Ridge для `C[t+h] − C[t]`, отдельно для h=1…7 сессий. Все ошибки ниже в RUB/USD. Результаты предварительные: существующий календарь реконструирован, доступность признаков имеет статус conditional EOD / pseudo-PIT.

На этих данных Core улучшает price-only на всех горизонтах, но снижение RMSE относительно RW составляет лишь 0.68% на h=6 и 0.22% на h=7. Подтверждённого преимущества перед RW нет. RUONIA/Brent ухудшают результат; добавление USD/CNH почти ничего не меняет. Эти выводы относятся к выбранным признакам, сетке alpha и режиму обучения.

## Методика и ограничения сравнения

- R1: `open, high, low, close, volume`. R2: неизменённый Core из `feature_scenarios_v1.json` (9 признаков, включая предыдущий funding). R3: Core + RUONIA + Brent; R4: R3 + USD/CNH. R5: Core + текущий funding, только диагностическая абляция `PIT_UNVERIFIED`, исключённая из основного сравнения.
- Train: 2022-04-26…2024-12-31; validation определяется **датой target** в 2025 году. На каждом h — 254 одинаковые тройки `(origin_date, target_date, horizon)` у Ridge, RW и AR(1). Первые origins находятся в декабре 2024 года; targets: 2025-01-03…2025-12-30. Горизонты считаются по существующему торговому календарю, без удаления строк и сжатия пропусков.
- На каждом origin допускаются только пары с `target_date ≤ origin_date` и `target_date ≤ 2024-12-31`. Следуя запрету использовать основной validation для обучения, **метки 2025 года никогда не входят в fit**, включая imputer/scaler. Окно расширяется до созревания последних train-меток, затем фиксируется. Поэтому это строгий train-only walk-forward, а не ежедневное дообучение на исходах 2025 года. На h=1 имеется одно уникальное окно, на h=7 — семь; число пар растёт с 670 до 676 для h=7 (для h=1: 682).
- Сохранённый AR(1) использовал prequential обновление по созревшим исходам validation. Сравнение с ним корректно по общим датам и ценовым единицам, **но режимы обновления обучения различаются**. RW/AR загружены из существующего `benchmark_calendar_v2`; эти артефакты и pipeline не менялись.
- Импутация медианой и стандартизация (population std) обучаются только на допустимой истории; intercept не штрафуется. Минимизируется `sum((y − intercept − Zβ)²) + alpha·sum(β²)`; NumPy реализация не требует новой зависимости sklearn.
- Alpha выбирается один раз для сценария/горизонта/преобразования/участка по pooled ценовому RMSE на трёх внутренних хронологических окнах origins: I/II полугодия 2023 и I полугодие 2024. В каждом внутреннем окне fit фиксируется на первом origin и использует только созревшие метки. Все внутренние targets предшествуют первому внешнему origin; случайного KFold нет. Сетка: `0.01, 0.1, 1, 10, 100, 1000`; минимум 100 пар. Для all-history во всех сценариях выбрано **1000, верхняя граница сетки**. Это ограничение: сетка после просмотра validation не расширялась. В S2 первое внутреннее окно пропущено из-за короткой истории.
- 154 начальных NaN предыдущего funding заполняются медианой допустимого train; настоящие нули остаются нулями. S2 отдельно переобучает R1 и R2 на одинаковых train-origins с наблюдаемым funding с 2022-12-06; validation-пары те же. В S2 528 пар train на h=1 и 516→522 на h=7. Это одновременно проверка обработки пропусков и изменения длины истории, поэтому эффект нельзя приписать только funding.
- CSV отсекаются по дате до числового разбора; benchmark Parquet читается с фильтром `split=validation`. 2026 год не использован для обучения, подбора или оценки. Хеши полных замороженных файлов вычислены для проверки их идентичности. B3 CSV, Core, PIT-каталог и исходные данные не изменялись.

Для log-return восстановление цены: `C[t]·exp(predicted_log_return)`, без дополнительной коррекции на Jensen bias. Его RMSE/MAE/bias также считаются по ценам. Лог-преобразование не даёт систематического улучшения: небольшие улучшения Core на длинных горизонтах соседствуют с ухудшением других сценариев. S2 не подтверждает преимущество Core над RW и хуже основного R2 на всех h.

R5 читает `swaprate_current` **только из frozen v2**. Проверяются SHA256 исходника против B3-конфигурации, совпадение индексов дат v2/B3/metadata, дата `begin`, source_dataset/source_sha256, совпадение OHLCV и предыдущего funding. Независимый исходный MOEX `TRADEDATE` и время публикации в v2 не сохранены: проверка дат подтверждает внутреннее выравнивание frozen v2, но не доказывает доступность текущего funding на forecast origin. Источник согласно существующему аудиту — MOEX contractresults USDRUBF/RFUD SWAPRATE. **По R5 нельзя делать вывод о реальной прогнозной полезности текущего funding.**

## Неопределённость

Для разности квадратов ошибок Ridge−RW рассчитаны Newey–West HAC SE (Bartlett, lag=max(20,h−1)), двусторонние normal-approximation p и нескорректированные 95% CI. Holm применяется отдельно к 28 сравнениям R1–R4×h основного delta-эксперимента, 28 сравнениям log-return и 14 сравнениям S2. R5 исключён из этих семейств. Семейства охватывают каждую отдельную постановку, а не все возможные последующие исследования.

**Значимого улучшения относительно RW после Holm нет.** Для delta обнаружено ухудшение R1/R3/R4 на h=1…2 (adjusted p<0.05). Выводы асимптотические: один validation-год, перекрывающиеся горизонты, режимные сдвиги и выбранный HAC bandwidth ограничивают их надёжность. Эти проверки не устанавливают значимость отдельных коэффициентов, сравнений с AR или попарных изменений наборов признаков. Полная таблица: [hac_comparisons_all.csv](../results/ridge_experiments/hac_comparisons_all.csv).

## Коэффициенты и важность

Для каждого сценария, преобразования и h сохранены стандартизованные по X коэффициенты со знаками, ranks, imputer/scaler, train bounds и первый origin использования в `coefficients_windows.csv`. Строки каждого origin ссылаются на `window_id`; это позволяет восстановить всю динамику, включая повторное использование одинакового fit. `coefficient_stability.csv` содержит доли положительных/отрицательных значений, число смен знака, средний rank и его std по всем origins. Единица коэффициента — RUB/USD на одну train-σ признака для delta, log-return на одну train-σ для log.

Примеры для основного delta (среднее по origins):

| Сценарий | Крупнейший по модулю коэффициент h=1 | h=7 | Наибольшая permutation ΔMSE, h=7 |
|---|---|---|---|
| R1 | volume +0.01868 | high −0.03079 | high +0.02851 |
| R2 | volume +0.01955 | spread_close_minus_cbr −0.11684 | spread +0.07368 |
| R3 | Brent −0.04657 | Brent −0.31096 | Brent +0.09171 |
| R4 | Brent −0.04673 | Brent −0.30948 | Brent +0.09203 |
| R5, диагностический | volume +0.01978 | spread −0.11728 | spread +0.07372 |

Высокая стабильность после начала 2025 года прежде всего отражает запрет дообучения на validation, а не устойчивость экономической зависимости. OHLC сильно коррелированы; `spread_close_minus_cbr = close − cbr_usdrub_effective` создаёт точную линейную зависимость в Core. Ridge распределяет веса между такими признаками; знаки, ranks и magnitudes зависят от стандартизации, alpha и состава X. **Коэффициенты не интерпретируются как статистически значимые или причинные эффекты.**

Permutation importance — диагностика на хронологическом validation без refit: 20 перестановок блоков по 20 сессий, seed 240112, среднее/std прироста MSE в ценовых единицах в квадрате. При перестановке close исходный якорь `C[t]` остаётся фиксированным: оценивается только роль close как регрессора. Коррелированные признаки могут подменять друг друга; отдельные перестановки нарушают OHLC/алгебраические связи и могут создавать нереалистичные комбинации. Положительная важность Brent внутри R3/R4 не означает, что добавление Brent улучшает прогноз против Core. Подробности ограничения: [официальная документация permutation importance](https://scikit-learn.org/stable/modules/permutation_importance.html).

## Артефакты и воспроизведение

Код: [benchmarks/ridge.py](../benchmarks/ridge.py), [runner](../scripts/run_ridge_experiments.py), [конфигурация](../configs/ridge_experiments.json), [тесты](../tests/test_ridge.py). В `results/ridge_experiments/{core,extended,log,s2}/` находятся OOS-прогнозы **до добавления actual**, scored predictions, сравнения на общих ключах, метрики, коэффициенты, importance, inner tuning и manifest. Всего 21 336 прогнозов: 3 556 core, 5 334 extended, 8 890 log, 3 556 S2.

Manifest фиксирует конфигурацию, пакеты, SHA256 защищённых источников, SHA256 LF-нормализованных файлов реализации, Git SHA `887a176d7f269eb8f98ef648843d4e57e6e80c58` и dirty status. Это SHA базы, **реализация при расчёте ещё не закоммичена**; точный код определяется сохранёнными source hashes. Предыдущие benchmark-результаты не перезаписываются; runner требует пустую папку каждого этапа.

Из корня репозитория с зависимостями `requirements.txt` (для нового прогона указать новый пустой output-root):

```powershell
python scripts/run_ridge_experiments.py --stage core --output-root results/ridge_reproduction
python scripts/run_ridge_experiments.py --stage extended --output-root results/ridge_reproduction
python scripts/run_ridge_experiments.py --stage log --output-root results/ridge_reproduction
python scripts/run_ridge_experiments.py --stage s2 --output-root results/ridge_reproduction --summarize
python -m unittest discover -s tests -p test_ridge.py -v
```

Все 14 Ridge-тестов прошли: созревание меток, train cap, независимость alpha от validation, неизменность прошлых прогнозов при изменении будущего, торговые горизонты/пропуски, funding/нули/S2, R5 date/source isolation, log-reconstruction, common-date comparison и воспроизводимость. Полный повторный real-data запуск core дал **побайтовое совпадение всех девяти CSV**; хеши в [reproducibility.json](../results/ridge_experiments/reproducibility.json). Все frozen B3-артефакты прошли `build_model_features.py --compare`.

Полный набор: 75 тестов, 73 прошли, 1 пропущен, 1 ранее существующий тест B4 не прошёл (`test_reproducibility_compare_and_input_immutability`): сохранённый funding-аудит содержит старый hash `docs/backtest_protocol.md`, изменённого после B4 в main. Сам файл протокола, код/артефакты B4 и входные данные в этой задаче не менялись; старый отчёт не пересоздавался ради прохождения проверки. `git diff --check` прошёл.
