# Benchmark Specification — USDRUBF

**Версия:** 1.0 · 2026-11-19 · Ответственный: A

## Базовые соглашения

`F_t` — рыночная цена USDRUBF на зафиксированном ежедневном прогнозном срезе. Шаг `h` в MVP — торговый день, при условии согласования этого решения. Курс ЦБ определяется как последнее **опубликованное** к срезу значение, а не курс за ту же календарную дату автоматически.

| ID | Модель | Формула | Параметры | Какие данные нужны |
|---|---|---|---|---|
| B0 | Random Walk | `F_hat(t+h|t)=F_t` | нет | ряд USDRUBF |
| B1 | Random Walk with Drift | `F_hat(t+h|t)=F_t+h*mu_hat_t` | среднее доступных исторических однодневных изменений | ряд USDRUBF |
| B2 | Spread Regression | `Delta_h F_t=beta_0+beta_1*b_t+sum_j beta_{j+1}*lag_j(b)_t+error`, `b_t=F_t-S_CBR_asof(t)` | регуляризация/лаги, выбор только на validation | USDRUBF + PIT курс ЦБ |
| B3 (опционально) | Autoregressive/Ridge | будущая разность на лаги ценовых изменений | число лагов, штраф | ряд USDRUBF |

B2 — **самостоятельная проверяемая гипотеза**, не свойство, доказанное спецификацией биржи. Спред не равен фандингу; форму и время расчёта фандинга следует проверять отдельно.

## Алгоритм для каждого горизонта

1. На origin `τ_t` получить последнее доступное значение USDRUBF `F_t` и обучающую историю с известными targets.
2. Построить `h`-шаговый прогноз отдельно для каждого `h=1,…,7`.
3. Записать прогноз до открытия target-значения.
4. Получив target, оценить ошибки на **общих датах** с другими моделями.

## Первые ожидаемые файлы

- `predictions_rw.parquet` или CSV: `model_id, model_version, forecast_origin, target_timestamp, horizon, prediction, train_end_timestamp, data_version`.
- `metrics_by_horizon.csv`: `model_id, horizon, n, mae, rmse, bias, rmse_ratio_vs_rw`.
- `benchmark_config.yaml` (конвенция временных срезов, дата начала, тренировка, переобучение).

**В день 1** утверждается спецификация и требования к входным данным; **в день 2** запускается первая реализация B0. Не создавать численные результаты до получения фактической истории.
