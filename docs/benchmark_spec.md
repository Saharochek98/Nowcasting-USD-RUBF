# Benchmark Specification — USDRUBF

**Версия:** 1.1 · 2026-11-19 · **Ответственный:** A

## Единые соглашения

`F_d` — цена последней **допустимой** сделки USDRUBF до 23:50 МСК торгового дня `d`, `forecast_origin=d 23:51:00 Europe/Moscow` — предварительное время выпуска прогноза, если котировки фактически доступны к нему. Прогнозируем аналогичную цену закрытия на следующие `h=1,…,7` **торговых дней**, не календарных.

Биржевой `settlement/clearing price` и курс ЦБ — не target. Если у origin нет свежей допустимой сделки, baseline не формирует стандартный прогноз; если у target нет допустимой цены, прогноз не оцениваем, но горизонт не переопределяем.

## Таблица моделей

| ID | Модель | Формула/идея | Информация |
|---|---|---|---|
| B0 | Random Walk | `F_hat(d+h|d)=F_d` | подтвержденная цена close proxy до 23:50 |
| B1 | Random Walk with Drift | `F_hat=F_d+h*mu_hat_d` | средняя доступных исторических изменений между торговыми днями |
| B2 | Spread / funding regression | `Delta_h F_d = beta0 + beta1*(F_d-S_CBR_asof(d)) + beta2*SwapRate_asof(d) + ...` | курс ЦБ и funding, **опубликованные** до origin; обучение и лаги только на train |
| B3 (опционально) | Ridge/AR | будущая разность цены на лаги ее изменений | цены и train-only стандартизация |
| M1 | PCA + прогнозная регрессия | статические факторы | PIT-панель |
| M2 | DFM + Kalman | динамические факторы | PIT-панель |
| M3 | DFM+ML | корректировка по историческим OOS-ошибкам | только ошибки с известной меткой |
| M4 | Interval calibration | интервалы / усадка дисперсии | train/validation без доступа к test |

B2 проверяет **гипотезу** возврата/коррекции спреда, не гарантирует предсказуемость. SwapRate не равен `F−S_CBR` и не должен рассчитываться задним числом из недоступной информации.

## Процедура B0

1. Построить торговый календарь USDRUBF и `F_d` по единому правилу свежести.
2. На `forecast_origin(d)` проверить, что `F_d` и все прочие данные уже доступны.
3. На каждом `h` выдать `prediction=F_d` для **h-го следующего торгового дня**.
4. Сохранить предсказание независимо от будущей валидности target.
5. После появления `F_{d+h}` пометить `scored` или `unscored` и сравнить с остальными моделями на одинаковом подмножестве.
