# Предложения новых признаков USDRUBF — review H11

**Дата:** 25.11.2026  
**Версия документа:** 1.1 — полный реестр кандидатов добавлен, P0-эксперимент не расширен.  
**Состояние GitHub при сверке:** `main` commit `9b1cba5d2e60af9de3699a5246646ba24c0a2065`, новых открытых PR нет.  
**Статус документа:** исследовательское **предложение**, не реализованные признаки и не утверждённый эксперимент.  
**Задача:** прогноз дневного рыночного `CANDLE_CLOSE` USDRUBF на 1–7 следующих **торговых** сессий, `conditional EOD / pseudo-PIT`.

## 1. Почему нужны новые признаки

В `main` уже есть результаты RW, AR(1), RW с drift, Ridge v1/v2, CatBoost Core v2 и XGBoost Core v2 на validation 2025. Ни один из факторных методов не показал статистически подтверждённого выигрыша над RW после заявленных HAC/Holm-проверок. CatBoost немного снижает RMSE на h=4/6/7, но это **exploratory**, а не независимое подтверждение. Простой дальнейший перебор алгоритмов и гиперпараметров на том же 2025 году повышает риск переобучения к validation.

В действующем плане команды есть H10 (**level vs delta**) и H11 (**относительные признаки**). **Предлагаемый следующий шаг — согласовать один ограниченный эксперимент H11**, не выполнять H10 одновременно и не открывать final test 2026 для выбора признаков.

**Разные версии входов:** B3 `features_daily_v1.csv` заморожен (`core` = 9 полей, без текущего funding). Экспериментальные Ridge v2 / CatBoost / XGBoost используют отдельный **Core v2 = 10 полей**, включая `swaprate_current` только при допущении `ASSUMED_AVAILABLE`, а не исторически подтверждённом PIT. Frozen исходные данные переписывать нельзя.

## 2. Кандидаты для первого эксперимента H11

Для всех формул `t` — торговая дата USDRUBF, известна полная свеча `t`; `C` — `close`, `V` — `volume`; `t-k` означает предыдущие *торговые сессии* в предварительном календаре USDRUBF, а не календарные дни. Любой признак с warm-up/пропуском остаётся missing и не заполняется будущими значениями.

| Приоритет | Признак | Точная предварительная формула | Из каких данных | Гипотеза / оговорка |
|---|---|---|---|---|
| **P0** | `logret_1` | `ln(C_t / C_{t-1})` | `close` | Краткосрочное изменение цены |
| **P0** | `logret_3` | `ln(C_t / C_{t-3})` | `close` | Краткосрочный импульс |
| **P0** | `logret_7` | `ln(C_t / C_{t-7})` | `close` | Недельный масштаб на торговой оси |
| **P0** | `range_rel` | `(High_t - Low_t) / Open_t` | `open, high, low` | Амплитуда дневных колебаний; не минутная realized volatility |
| **P0** | `volume_ratio_20` | `V_t / mean(V_{t-19},…,V_t)` | `volume` | Нетипичная активность относительно 20 сессий; знаменатель должен быть положительным |
| **P0** | `distance_sma20` | `(C_t - mean(C_{t-19},…,C_t)) / mean(C_{t-19},…,C_t)` | `close` | Отклонение от локального уровня; знаменатель должен быть положительным |

**Почему шесть, а не все предложения:** фиксируем небольшое число интерпретируемых индикаторов до очередного прогона. Списки окон 1/2/3/5/7/10/14/20, RSI, ATR и других факторов сохраняются как *идеи*, а не как сетка для подбора по validation.

## 3. Полный реестр предлагаемых признаков (backlog, **не** утверждённый набор для модели)

Ниже сохранены **все группы идей**, включая разные окна одного индикатора, которые обсуждались ранее. Приоритеты означают *порядок исследовательской проверки*, а не доказанную полезность. Наличие ряда в CSV не равнозначно его доступности к `forecast_origin`. Кандидаты, выбранные в разделе 2, помечены как **P0**; остальные — на будущее. Не запускать полный список как сетку для подбора по уже многократно использованному validation 2025.

| Группа | Полный список идей / пример расчёта | Что уже есть и что нужно проверить | Очередь / решение |
|---|---|---|---|
| **Логарифмические доходности** | `logret_k = ln(C_t/C_{t-k})` для **k = 1, 2, 3, 5, 7, 10, 14, 20 торговых сессий** | `close` уже есть. Только прошлые полные свечи; для первых k наблюдений — warm-up/missing | **P0:** 1, 3, 7. **P1:** 2, 5, 10, 14, 20 — отдельно, не подбирать окна массово |
| **Дневной диапазон** | `range_rel = (High_t − Low_t)/Open_t` | Есть OHLC. Это нормированный размах, **не** realized volatility по минутным сделкам | **P0**, включить в H11-REL-01 |
| **Историческая волатильность** | `ATR14/Close_t`; стандартное отклонение дневных `logret_1` за фиксированное окно (например, 10 или 20 сессий) | Есть OHLC. Для ATR зафиксировать определение True Range с предыдущим `close`; для std — окно и `ddof`; учитывать warm-up | **P1**, следующий согласованный тест |
| **Тренд / возврат к среднему** | `distance_sma20 = (C_t − SMA20(C)_t)/SMA20(C)_t`; `RSI(14)` | Есть `close`. Для RSI заранее зафиксировать способ сглаживания (например, Wilder) и обработку нулевых средних потерь | **P0:** distance/SMA20. **P1:** RSI14 |
| **Объём** | `volume_ratio_20 = V_t/SMA20(V)_t`; `volume_change_1d = V_t/V_{t-1} − 1` при положительном предыдущем объёме; возможен `log1p(V_t)` | Есть `volume`. Для SMA включена текущая **завершённая** свеча; при нулевом знаменателе — missing/оговорённое правило | **P0:** ratio20. **P1:** дневное изменение и log-объём |
| **Фандинг (SwapRate)** | Разность `funding_prev_t − funding_prev_{t-1}`; накопленные суммы за **1, 3, 5** доступных торговых сессий, например `sum_{j=0}^{k-1} funding_prev_{t-j}` | В замороженном v2 есть `swaprate_prev_session`, но **154 начальных пропуска**. Нули — наблюдения. Историческое время публикации funding не подтверждено; `swaprate_current` в Core v2 только `ASSUMED_AVAILABLE` | **P1** — отдельный аудит/абляция; не делать суммы через missing и не подставлять будущий funding |
| **Открытый интерес (OI)** | `OI_change_1d`, `OI_change_3d`, `OI_pct_change_1/3 = OI_t/OI_{t-k} − 1`; `OI/Volume` при проверенных единицах и ненулевом объёме | `OPENPOSITION` **обнаружен в локальной исходной выгрузке MOEX contractresults**, но отсутствует в frozen v2/B3. Нужны определение/единицы, торговая дата и фактическое `available_at`, особенно для OI того же дня | **P1/P2**, только после аудита A и версии источника; при необходимости использовать OI предыдущей подтверждённо доступной сессии |
| **Календарь и потоки** | День недели; рабочая суббота; число календарных дней до/после ближайшей торговой сессии; расстояние до месяца/квартала (только по заранее известному календарю) | Есть provisional trading calendar. Специальные выходные и изменения режима торгов требуют проверки; «до следующей сессии» нельзя вычислять из будущих наблюдений/непредсказанного задним числом календаря | **P1/P2**, отдельная календарная гипотеза |
| **Налоговые даты** | Дней до следующего известного срока крупных налоговых платежей; флаг интервала вокруг срока, а не неизменный «25–28» | Требуется исторический налоговый календарь РФ с переносами выходных и изменениями правил; учитывать, что календарный срок должен быть известен на origin | **P2**, собрать источник/архив до расчётов |
| **Максимальный фандинг `L₂`** | Доля прошлых k торговых сессий, когда исторический funding достигал соответствующего лимита по модулю/нужному знаку; отдельно положительный/отрицательный режим | Нужны исторические значения параметра биржи `K₂`, корректная база расчёта лимита, даты действия правил и доступность окончательного SWAPRATE. Без этого нельзя пометить «максимальный штраф» по одному большому числу | **P2**, сначала подтверждение спецификации/истории параметров |
| **Order Flow Imbalance (OFI)** | Дисбаланс заявок или агрессивных сделок за предыдущую торговую сессию **по заранее выбранному определению OFI** | Требуются исторические события стакана или лента сделок с направлением агрессора, временные метки и PIT. Из дневных OHLCV и общего объёма строго восстановить нельзя | **P3**, отложить до появления качественного intraday источника |
| **Вечерняя динамика OI** | Изменение OI непосредственно за вечернюю сессию, относительный всплеск к прошлым вечерам | Нужен внутридневной архив OI и точные исторические границы сессии/торговой даты; дневное `OPENPOSITION` не позволяет выделить вечер | **P3**, отложить |
| **Дополнительные внешние ряды** | Изменения RUONIA, Brent и USD/CNH относительно известных прошлых наблюдений | Ряды есть в полной v2; для исторических публикаций/ревизий и часовых срезов сохраняются допущения, особенно у Brent/USD-CNH | **Sensitivity**: не смешивать с первым H11 |

**Принцип расчёта:** `t-k` — ровно k **прошлых торговых сессий**, а не k календарных дней; сначала соблюдаются допустимые торговые даты и публикационные лаги, затем вычисляется признак. Если окно не полностью наблюдается, сохранять missing по заранее определённому правилу. Для ставок/фандинга не смешивать доли, проценты и денежные единицы; для OI сначала подтвердить смысл числителя и знаменателя.

**Разделение по исполнению:** сейчас на review выносится ровно **6 P0** из раздела 2; расширенные окна доходностей, ATR, RSI, funding и OI — это **исследовательский backlog**, а не автоматически разрешённые колонки следующей модели.

## 4. Предлагаемый единый протокол H11-REL-01 — **согласовать до реализации**

**Главное сравнение:** фиксированный алгоритм и политику гиперпараметров взять из уже сохранённого CatBoost Core v2, без новой широкой настройки по 2025 году. Горизонты `h=1,…,7`; target сохранять как `C_{t+h}-C_t`, цена восстанавливается как `C_t + prediction`.

- **R0 (контроль):** замороженный Core v2 (10 полей), с чёткой маркировкой `swaprate_current=ASSUMED_AVAILABLE`.
- **R1 (добавление):** те же Core v2 + 6 полей P0 из таблицы.
- **R2 (замена, только если заранее согласовано):** Core v2 с заменой четырёх сырых `open/high/low/close` на относительные показатели P0; `volume` и прочие базовые поля сохраняются. **Оговорка:** `spread_close_minus_cbr` вместе с CBR всё равно несёт информацию об абсолютном уровне, поэтому R2 не следует называть полностью «безуровневой» моделью.

Для сравнения обязательно использовать **одинаковые** `(origin_date, target_date, horizon)`, одинаковые допустимые training windows / зрелые h-шаговые метки, согласованное правило warm-up с 20-дневными SMA и одинаковую обработку пропусков. Все rolling считают только из свечей не позже `t`. Обучаемые параметры, включая imputer, — **train-only на каждом origin**. Старые результаты RW/Core v2 не изменять; если train-окно изменится из-за warm-up, создать явно названный matched контроль, а не сопоставлять несопоставимые запуски.

**Отчёт:** RMSE, MAE, bias и `n` по каждому h; сравнения с RW и между R0/R1/R2 на тех же ключах; HAC с явно заявленным семейством и поправкой Holm; влияние на пропуски и стабильность важности; reproducibility (SHA/manifest/seed/code, no-lookahead tests). Год **2025 уже использован многократно** и является только exploratory validation. Final test 2026 не оценивать до одобрения фиксированного протокола.

**Перед запуском Research Lead B должен согласовать:** (a) H11 вместо H10 на этом шаге; (b) именно шесть P0 и окна; (c) R0/R1 или R0/R1/R2; (d) модель/гиперпараметры и политику missing/warm-up; (e) использование Core v2 с текущим funding как **допущение**; при необходимости отдельно назначить core=9 как sensitivity.

## 5. Вопрос Total Return

Не менять утверждённую целевую переменную дневной цены USDRUBF на неформальный `delta CLOSE − накопленный funding`. Доходность позиции — отдельная задача: нужны направление, клиринговая/расчётная цена, лот, календарь удержания, выплаты funding, комиссии и проскальзывание. Будущий реализованный funding не может быть признаком на origin `t`. Если команда будет исследовать торговую стратегию, для P&L нужен самостоятельный протокол.
