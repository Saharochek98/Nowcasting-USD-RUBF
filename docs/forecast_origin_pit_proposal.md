Разница вызвана только переводами строк (`git ls-files --eol`: `i/lf w/crlf`);

|---|---:|---|
| 23:59:59 | 1083 | 26.04.2022–18.11.2026 |
| 23:59:41 | 29 | 05.09.2022–24.11.2022 |

| 19:30:22 | 22 | 19.03.2024–03.06.2025 |

Итого 42 метки 23:59:41/42 и 35 меток 19:30:21/22. Полный список всех
77 дат и точных меток: [unusual_candle_ends.csv](../results/moex_availability_monitor/unusual_candle_ends.csv).
Машиночитаемые количества: [candle_end_counts.csv](../results/moex_availability_monitor/candle_end_counts.csv).
Пересчёт воспроизводится без сети:

```powershell
$r = Import-Csv data/raw/USDRUBF_daily_2026-11-18.csv
$r | Group-Object { $_.end.Substring(11) } | Select-Object Name,Count
$r | Where-Object { $_.end.Substring(11) -ne '23:59:59' } | Select-Object begin,end
```

В 2022/2023/2024/2025/2026 соответственно 173/254/256/254/223 строки;
необычных меток 42/0/13/22/0. Все `begin` имеют время `00:00:00`.
До 23.03.2026 — 990 строк, с этой даты — 170; все 223 строки 2026 года имеют
`end=23:59:59`. В локальном окне 16–30.03.2026 (11 свечей) обе стороны перехода
одинаковы по `begin/end`. **Смена структуры этих меток не обнаружена**;
это не доказывает неизменность состава сделок или публикационного лага.

По [справочнику candle endpoint](https://iss.moex.com/iss/reference/409?lang=en)
возвращаются данные HLOCV для свечного графика. `begin` и `end` в снимке — метки
границ свечи, не timestamps запроса. Справочник не объясняет отклонения на секунды,
точный алгоритм дневной агрегации или SLA финальности. Поэтому `end` не трактуем
как время последней сделки, окончание биржевой сессии или `available_at`.
В README проекта упоминается прежняя сверка 35 баров с минутными данными;
сами сравнительные артефакты не представлены в исследованных материалах,
новая независимая сверка не выполнена. Причина 19:30 остаётся **unknown**.

## 4. Задержка ISS и гипотеза 00:05

[MOEX a7939](https://www.moex.com/a7939) описывает бесплатные данные ISS с
15-минутной задержкой и подписку на real-time. [MOEX a2920](https://www.moex.com/a2920)
перечисляет справочные данные, сделки, лучшие котировки, текущие/исторические
итоги и данные графиков. [Страница срочного рынка](https://www.moex.com/ru/derivatives/lastdata.aspx)
явно маркирована задержкой 15 минут; [карточка USDRUBF](https://www.moex.com/ru/derivatives/perpetual-futures/USDRUBF)
содержит такое же предупреждение и ссылку на подписку.

Это подтверждает общий режим бесплатной рыночной информации. В проверенных
источниках нет полного перечня endpoint × правила задержки; reference/409
не содержит отдельного обещания `candles.json?interval=24`, времени завершения
агрегации или запрета дальнейших исправлений. Нельзя распространять задержку
на каждое справочное/историческое поле или считать её ровно 15 минутами после `end`.
Ссылка на developer manual `https://fs.moex.com/files/8888` вернула timeout
через веб-инструмент; подтверждений из недоступного PDF не делаем.

Публикация сделки, обновление текущего бара и окончательная фиксация OHLCV —
разные события. Проверенная документация не задаёт временную связь всех трёх
для дневного USDRUBF. Дополнительный лаг формирования окончательного бара
**неизвестен**, а не равен нулю. Подписка устраняет заявленную задержку real-time
потока в рамках её условий, но не даёт исторические винтажи автоматически.

`23:50 + 15 минут = 00:05` следующего календарного дня — условная арифметическая
гипотеза для информации о сделке. **00:05 МСК не является гарантированным временем
доступности окончательного дневного CLOSE**, ни до, ни после 23.03.2026.
Также нет оснований заменять эту гипотезу окончанием клиринга в 00:30.

## 6. Аудит факторов v2

Снимок: 1160 × 30, SHA-256
`da5b582e622ce5d3efb6fb619c0b9258dc15fc7d18b6d76860ce5fb021107103`.
Каталог: [feature_availability_catalog.csv](feature_availability_catalog.csv).
Статус относится к **исторической доступности конкретного выбранного значения**:
`verified` — есть источник и свидетельство доступности к origin;
`assumed` — явно задано недоказанное предположение;
`unknown` — даже достаточное правило доступности пока не установлено.
Ни одна группа текущего исторического снимка не получает `verified` только за
положительный возраст. Подтверждённое расписание публикации само по себе также
не доказывает доступность всех исторических ревизий из сегодняшней выгрузки.

Правила непосредственно из `build_external_features.py`:

- OHLCV: все исходные значения той же даты; допустимы после полной свечи в
  conditional EOD. Поле `value` постоянно нулевое и не предлагается как фактор.
- Курс ЦБ: последний `effective_date <= t`; время публикации не используется.
  Дата действия не равна дате публикации. Уже опубликованный курс, действующий
  с завтрашнего дня, в v2 сознательно не выбран. Отдельная смена схемы требует A.
- Текущий funding: `SWAPRATE[TRADEDATE=t]`, без публикационного среза;
  исключить из основного разрешённого набора до подтверждения.
- Предыдущий funding: ровно предыдущая торговая дата USDRUBF, не календарный
  вчерашний день. Условно допустим; один торговый лаг не гарантирует публикацию.
  `swaprate_source_trade_date` и `swaprate_available_assumed` относятся **только**
  к предыдущему funding; флаг означает заполненность, а не проверенный PIT.
- Ключевая ставка: as-of по дате записи `<=t`; условное отождествление с действующим
  уровнем. Нужна сверка дат решений, вступления в силу и исключительных изменений.
- RUONIA: `reference_date<t` и **дата** `DateUpdate<=t`; timestamp обрезается до
  даты при отборе. Время в строке не гарантирует первый выпуск, часовое сравнение
  с origin не выполнено. Для строгого PIT исключить до архивов/as-of по времени.
- Brent: EIA Europe Brent Spot FOB, **не фьючерс**; последняя дата `<=t−10`
  календарных дней. Лаг 10 — предположение, не установленный срок EIA; ревизии
  и исторические сроки первого выпуска не проверены.
- USD/CNH: последняя дата поставщика `<t`, без установленного timezone и cut-off.
  `Price` не подтверждён как BID/ASK/MID; нельзя переименовать в BID. Формальная
  дата раньше t недостаточна для гарантии доступности. Строгий PIT исключает
  до уточнения; условный эксперимент — только с явным одобрением предположения A.
- Спред `close − cbr_usdrub_effective`: доступен не раньше обоих компонентов;
  наследует их предположения. Это известное значение на origin, не будущий target.

Независимо пересчитаны пропуски: текущий funding 153, предыдущий 154,
исходная дата предыдущего funding 1; остальные столбцы заполнены.
Описанные в словаре проблемы качества USD/CNH не исправлялись.
Метаданные дат, возрастов, страниц PDF и булев флаг не объявляются независимыми
экономическими признаками. Рекомендуемый условный набор для обсуждения:
OHLCV, действующий курс ЦБ, предыдущий funding, действующая ключевая ставка,
лагированные RUONIA/Brent, спред; USD/CNH — отдельное более слабое допущение.
Для **строгого PIT** все строки с `assumed/unknown` должны быть исключены либо
заменены архивными версиями с проверенными timestamps. Текущая панель такой
строгий эксперимент не обеспечивает. Лаги по RMSE не подбирались.

## 7. Варианты forecast origin для решения A

| Вариант | Определение | Строгость / реализуемость | Внешние факторы и архивы |
|---|---|---|---|
| A: conditional EOD | после предполагаемой доступности полной свечи t, точный час unknown | реализуем на текущем снимке; pseudo-PIT | явные допущения каталога; исторические винтажи отсутствуют |
| B: фиксированный час | выбранный час следующего календарного дня МСК после измерения достаточности | сейчас гипотеза, не готов к утверждению | брать только available_at<=cut-off; современные наблюдения не доказывают прошлое; нужны архивы по режимам |
| C: фактическая доступность | после подтверждённого появления полной свечи t | сильнейший при наличии доказательств; исторически сейчас невоспроизводим | timestamp получения, версия ответа, правило финальности и архивы ревизий для каждого компонента |

Для всех вариантов `available_at(x, vintage) <= forecast_origin(t)`;
`available_at(spread)=max(available_at(close),available_at(CBR))`.
Финальная свеча не определяется отсутствием изменений несколько запросов подряд.
Вариант C требует подтверждения завершённости со стороны источника/правил,
а не только `first_seen`. Монитор даёт интервально наблюдаемое появление версии:
между прошлым успешным ответом без неё и текущим успешным ответом с ней;
при первом запросе левая граница неизвестна. Ошибки расширяют неопределённость.

Пересечение полуночи не сдвигает target label: origin(t) может быть календарно
позже t; h считается по календарю USDRUBF. При задержке до начала следующей сессии
нужно явно зарегистрировать, что прогноз уже не до начала следующего торгового
дня, и решить с A, выпускать/пропускать такой origin. Нельзя незаметно включать
частичную свечу следующего дня. Сессии выходного дня делают эту оговорку особенно
важной. Более поздний origin не разрешает автоматически больше факторов в
существующем EOD-бэктесте: это изменение спецификации эксперимента.

Согласовать с B (Research Lead): вариант и критерий перехода из conditional EOD; список разрешённых
факторов и обработку пропусков; допустимость текущего funding; выбор действующего
либо уже опубликованного курса ЦБ; исключение/допущения USD/CNH и ревизий RUONIA/EIA;
реакцию на опоздание свечи, сверку торговой даты и независимый календарь;
политику архивирования и финальности. Никакие решения A здесь не приняты.

## 8. Следующее измерение и границы B1

Скрипт и [инструкция](moex_candle_monitoring.md) готовы для ручного конечного окна
через полночь и после клиринга. Непрерывный мониторинг не запускался. Нужны несколько
