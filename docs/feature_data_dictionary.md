# Словарь факторной панели USDRUBF v2 — B2

Дата аудита: 23.11.2026. Версия панели не меняется: **1160 строк × 30 столбцов**,
26.04.2022–18.11.2026, одна строка на метку дневной свечи USDRUBF.
Файл: `data/processed/model_dataset_usdrubf_all_features_v2.csv`.
SHA-256: `da5b582e622ce5d3efb6fb619c0b9258dc15fc7d18b6d76860ce5fb021107103`.
Статус словаря: полный по существующей схеме; предложения о применении требуют
review A. Режим данных: **conditional EOD / pseudo-PIT**.

## Назначение и временная постановка

Панель предназначена для исследования дневной рыночной цены USDRUBF на 1–7
следующих торговых дат. `C_t=close_t` — исходный `CANDLE_CLOSE` MOEX ISS RFUD
`interval=24`, не официальный USD/RUB и не расчётная цена клиринга.
`close_t` может быть известным уровнем на origin(t); будущий `close_{t+h}` —
обучающая метка только после её доступности. При преобразовании в изменения,
доходности или supervised target действуют ограничения `backtest_protocol.md`;
такие новые столбцы в v2 не добавлялись.

`forecast_origin(t)` находится после доступности **полной** свечи t. Исторический
час неизвестен; `end`, 23:50, 00:05 или конец клиринга не заменяют `available_at`.
Дата origin может календарно следовать за t; горизонт считается по календарю
USDRUBF, включая его предварительные ограничения. Исходные свечи не сдвигаются.
Подробности B1: [предложение origin](forecast_origin_pit_proposal.md).

Для каждого входа и его винтажа требуется `available_at <= forecast_origin`.
В текущей панели нет колонок с доказанным `published_at/available_at`.
Предполагаемый лаг ограничивает дату наблюдения, но не подтверждает публикацию
и не устраняет ревизии. Машиночитаемый [каталог](feature_availability_catalog.csv)
содержит по записи на каждый столбец. Определения статусов относятся к исторической
доступности выбранного значения, а не к проверенности его названия/единицы.

## Источники и фактические as-of правила

Builder: `scripts/build_external_features.py`; использует исходные выгрузки,
не обращается к сети. Большинство внешних исходников в checkout отсутствует;
их имена и контрольные суммы сохранены в прежнем словаре v2. Выводы о содержимом
этих отсутствующих файлов ограничены кодом и документацией, не новой сверкой raw.

| Группа | Фиксированный source file | Что делает builder |
|---|---|---|
| S1 | `USDRUBF_daily_2026-11-18.csv` | Сохраняет 8 исходных полей, добавляет date из begin; сортировка/уникальность проверяются |
| S2 | `RC_F01_01_2020_T21_11_2026.xlsx` | При номинале 1 выбирает по `bisect_right` последний effective_date≤t |
| S3 | `contractresults-USDRUBF-26042022-20112026.csv` | Выбирает SWAPRATE[t] и SWAPRATE[предыдущая метка USDRUBF]; пропуски сохраняет |
| S4 | `CBR_key_rate_from_pdf_2020-2026.csv` либо `cbr_hd_base_keyrate*.pdf` | `asof(reference_date≤t)`; PDF page переносится как provenance |
| S5 | `RC_F01_01_2020_T19_11_2026.xlsx` либо `normalized_ruonia_2020-2026.csv` | Перебирает DT от последней к первой среди DT≤t−1; принимает первую с date(DateUpdate)≤t |
| S6 | `RBRTEd.xls` либо `normalized_brent_eia_1987-2026.csv` | `asof(observation_date≤t−10 календарных дней)` |
| S7 | `USD to CNH Historical Exchage Rates.csv` | `asof(provider Date≤t−1 календарный день)` |
| S8 | Компоненты S1+S2 из панели | Decimal-разность CLOSE и курса ЦБ, формат 4 знака после запятой |

As-of по дате здесь — выбор последней подходящей записи источника, **не**
полноценный as-of по опубликованному винтажу. RUONIA дополнительно использует дату
обновления, но сравнение часов отсутствует. Последнее не равнозначно ошибке для
любого EOD-origin: конкретная доступность зависит от реального часа origin.

## Подтверждённые правила и оставшиеся допущения

- S1: семантика поля и происхождение подтверждены на уровне endpoint/снимка;
  окончательная историческая доступность неизвестна. Реформа 23.03.2026 не
  разрешает автоматически сдвигать даты или менять состав candle.
- S2: действующий курс отличается от последнего уже опубликованного. Выбор
  effective_date≤t консервативен относительно ещё не действующего курса, если
  публикация состоялась по регламенту. Он может не использовать опубликованный
  сегодня курс на завтра. Это недоиспользование информации, а не разрешение
  автоматически заменить ряд. Исторические времена/исправления выгрузки не проверены.
- S3: текущий и предыдущий funding различаются по торговой дате. Общие сведения
  о публикации после 18:00 не подтверждают весь исторический endpoint. Формула,
  расчётный период, публикация и начисление в клиринг — разные события.
- S4: объявленная новая ставка и действующий уровень могут различаться до даты
  вступления решения в силу. v2 содержит действующий уровень; announcement surprise
  не выделен. Календарное правило 13:30 не переносится на все внеочередные решения.
- S5: нормативная публикация RUONIA и запрет её изменения подтверждены действующей
  методологией; прежнее общее опасение B1 о свободных ревизиях ставки сужено.
  Смысл DateUpdate как первой публикации, ошибки выгрузки и соблюдение сроков
  конкретными записями не установлены. Календарь ЦБ отличается от календаря USDRUBF.
- S6: 10 дней — существующее предположение панели. Release dates на странице EIA
  и винтажи ALFRED позволяют будущую проверку, но не доказывают, что любой выбранный
  исторический XLS-уровень был доступен за 10 дней. Дополнительный лаг не назначен.
- S7: сведения о timezone интерактивных графиков не определяют timezone экспортной
  historical таблицы. Тип `Price` и финальность не установлены. Условие Date<t
  формально соблюдено; достаточность одного дня неизвестна.
- S8: единицы совместимы; `available_at(spread)=max(available_at(close),
  available_at(CBR))`. Известность одного компонента не разрешает весь спред.

Проверяемые ссылки и пределы исторического охвата: [источники S1–S8](../reports/feature_pit_audit.md#s1).
Ни один общий график не записан как фиктивный timestamp конкретного наблюдения.

## Пропуски, качество и воспроизводимость

Независимо проверены: 1160 уникальных упорядоченных дат; совпадение всех восьми
raw-полей с панелью; 153 пустых `swaprate_current`, 154 пустых `swaprate_prev_session`,
одна пустая `swaprate_source_trade_date` (первая строка). Других пустых значений нет.
Первый текущий funding — 05.12.2022, предыдущий — 06.12.2022.
Пустота не заменяется нулём: нулевой funding может быть экономически допустимым.
Все 1160 значений `value` равны 0.

Наблюдаемые возраста: курс ЦБ 0–12, RUONIA 1–14, Brent 10–14, USD/CNH 1–3
календарных дня. Это описательные проверки, не выбор лагов по качеству модели.
Исходные `end`: 1083 обычных, 42 около 23:59:41/42 и 35 около 19:30:21/22.
Причина отклонений неизвестна; значения не исправлялись.

Прежний словарь сообщает 7 несогласованных OHLC-строк в исходном USD/CNH,
3 исходные даты используются в панели; повторная raw-сверка невозможна без экспорта.
Новый локальный `results/moex_minute_audit/comparison.csv` содержит 35 дат × 4 окна:
полное совпадение OHLCV для окна до 19:30 лишь 9/35, для остальных окон 0/35.
Он не доказывает универсальную агрегацию всех 35 баров и ничего не измеряет о
первой публикации. Этот файл и его скрипт сохранены без изменений; сеть не запускалась.

Обнаруженная в B1 несовместимость calendar API исправлена в B2: builder и его
проверки читают фактическое поле `is_trading_day_expected` вместо несуществующего
`forts_market_trade_date_expected`. Календарь, даты панели и алгоритмы лагов
не изменены. Синтетические тесты используют ту же схему во временном файле.
Полная пересборка из внешних исходников всё ещё не выполнена: исходники отсутствуют.

## Предложение об использовании

Подробная [политика лагов](feature_lag_policy_proposal.md): A — условные кандидаты
OHLCV, действующий курс, предыдущий funding, ключевая ставка, спред; B — RUONIA,
Brent и USD/CNH для дополнительной проверки/отдельного сценария; C — текущий
funding и постоянное value. Все 16 метаданных служат аудиту.
Это предложение B2, не утверждённый allowlist и не изменение интерфейса модели.
При требовании строгого исторического PIT ни одна текущая группа не имеет полного
доказательства доступности к каждому origin; нужен архив/документированный срез.
