# Ручное наблюдение за дневной свечой MOEX

Инструмент: `scripts/monitor_moex_candle_availability.py`, Python 3.9+,
стандартная библиотека; сеть нужна только для реального запроса.
Запускать из корня репозитория. По умолчанию выполняется **один запрос**;
периодический опрос включается только явным `--duration` в секундах.

```powershell
python scripts/monitor_moex_candle_availability.py --once
```

Без `--date` каждый запрос получает дневные свечи за последние 60 календарных
дней по текущую московскую дату с обратной сортировкой ISS. Это ограниченный
диапазон (меньше страницы 500 дневных строк); запрос не принимает самую старую
страницу полной истории за последнюю. При отсутствии данных за весь диапазон
пишется `empty`; это не поиск произвольно давней последней свечи.
Все полученные свечи записываются, включая последние и текущую, если она есть.
Диапазон пересчитывается после полуночи, поэтому вчерашняя свеча остаётся в нём.

Для окна конкретной свечи и отложенного запуска укажите дату **метки свечи**,
время старта с offset и длительность. Пример для 23 ноября 2026, 23:40–01:40 МСК:

```powershell
python scripts/monitor_moex_candle_availability.py --date 2026-11-23 --start-at 2026-11-23T23:40:00+03:00 --duration 7200 --interval 60 --timeout 20
```

Это пример ручной команды, не назначенное задание и не выполненное измерение.
Перед запуском выбрать подходящий торговый день. `--start-at` в прошлом означает
немедленный старт; длительность отсчитывается от фактического начала опроса,
не от указанного прошедшего часа. Без `--date` фиксируются также соседние свечи.
`Ctrl+C` завершает работу, уже записанные строки сохраняются.

Результат по умолчанию:
`results/moex_availability_monitor/observations.csv`; можно задать другой CSV через
`--output`. Запись в `data/` запрещена. Не направляйте output на иные существующие
артефакты и не запускайте два процесса с одним output. Существующий журнал с
совместимым заголовком дополняется; состояние свечей восстанавливается из него.
Для независимого наблюдения выбрать новый output. `run_id` различает запуски.

## Что записывается

- `requested_at`, `received_at`: локальное время клиента с `+03:00`, отдельное
  поле `timezone=Europe/Moscow`. На Windows без базы IANA применяется UTC+3,
  корректный для современных наблюдений; синхронизировать часы машины.
- URL, HTTP-статус (пустой при сетевой ошибке), ошибка, заголовки Date/Retry-After,
  SHA-256 тела ответа, metadata свечей. Время сервера не заменяет время клиента.
- Все восемь стандартных полей свечи; `candle_json` сохраняет также любые новые
  поля. Парсинг идёт по именам `columns`, не по фиксированным позициям.
- `first_seen`: свеча впервые встретилась **в этом журнале**, не обязательно
  впервые появилась на сервере. `first_seen_at` — время получения ответа.
- `changed`: изменилось любое поле свечи; `unchanged`: поля совпали.
  `previous_seen_at` помогает установить предыдущую успешную точку наблюдения.
- `empty` и `error`: запрос не дал свечей / завершился ошибкой. Не стирают историю
  последней успешно увиденной версии. Удаление отдельной свечи из ответа не
  трактуется как финальность; для поиска пропажи сравнить наборы `begin` по времени.

Один запрос может дать несколько строк с общими временами/хешем: это разные
свечи одного ответа. Возвращённые поля возможной финальности сохраняются в JSON,
но монитор не назначает им интерпретацию без документации MOEX.

Таймаут настраивается; минимум между завершением запроса и следующим — 15 секунд,
по умолчанию 60. Немедленных повторов нет; `Retry-After` увеличивает паузу
(число секунд либо HTTP-date). Если следующая попытка выйдет за длительность,
процесс завершается. Последний запрос может завершиться позже конца окна на
время сетевого ожидания; полной гарантии жёсткой wall-clock границы нет.
Режим `--once` возвращает код 1 при ошибке, 0 при успешном ответе/пустом наборе;
при периодическом опросе ошибки остаются в CSV, завершение окна имеет код 0.

## Как интерпретировать

Первое появление версии наблюдаемо лишь в интервале между успешными запросами.
При запуске на уже существующих исторических свечах левая граница неизвестна.
Сравнивать отдельные свечи по `begin`, учитывая всю OHLCV, не только CLOSE.
**Стабильность, `end=23:59:59`, истечение 15 минут и завершение клиринга не
доказывают окончательность.** Нужны последующие контрольные снимки и документация
источника. Новые замеры не подтверждают историческую доступность того же значения.
Журнал не загружается в модели и не меняет target или лаги панели v2.

Однократная попытка B1 сохранена отдельно в `api_probe.json`: соединение не
установлено 23.11.2026. `observations.csv` с измерением закрытия пока не создан;
тестовые ответы туда не записывались. `unusual_candle_ends.csv` и
`candle_end_counts.csv` — аудит локального снимка, не live-наблюдения.

Автономные тесты без сетевых запросов:

```powershell
python -m unittest discover -s tests -p "test_moex_candle_monitor.py" -v
python -m unittest discover -s tests -p "test_external_features.py" -v
```
